# Chapter 12: SRv6 and the Road Ahead

Segment Routing separates two ideas: a path written as a list of segments, and the data plane that carries the list. On MPLS the segments are labels. **SRv6** carries them in **IPv6** instead. Every segment is an IPv6 address, the core is ordinary IPv6 routing, and the services of this book, L3VPN, EVPN, and traffic engineering, work without MPLS at all. This last chapter explains how, runs an L3VPN over SRv6, and closes with how to choose between the options.

An SRv6 **SID** is a 128-bit IPv6 address with internal structure:

- The **locator** identifies the node. Each node owns a locator prefix, for example `fcbb:bb00:2::/48`, and advertises it in IS-IS like any other IPv6 prefix. Routers that know nothing about SRv6 still route toward it correctly.
- The **function** tells the owning node what to do with the packet. Functions are called **behaviours** and are standardised in RFC 8986. Common ones:

| Behaviour | Meaning | MPLS analogue |
|---|---|---|
| End | Endpoint: move on to the next segment | Node SID |
| End.X | Move on, and send out of a specific link | Adjacency SID |
| End.DT4 / End.DT6 / End.DT46 | Decapsulate and look up in a VRF's IPv4 / IPv6 / both tables | Per-VRF VPN label |
| End.DX4 / End.DX6 | Decapsulate and send to a specific next hop | Per-CE VPN label |

The head end encapsulates the customer's packet in a new IPv6 header whose **destination address is the active segment**. If the path has more segments, it adds a **Segment Routing Header** (SRH, RFC 8754) listing them, with a **segments left** counter. Each node that owns the active SID performs its behaviour, decrements the counter, and copies the next segment into the destination address. Routers in between see only an IPv6 packet and route it on its destination.

Most L3VPN traffic needs only one segment, the egress PE's VPN SID, so it carries no SRH at all.

With the common **F3216** format, a 32-bit block is followed by 16-bit uSIDs. The address `fcbb:bb00:0013:0002:e000::` means "go to node 13, then to node 2, then run function e000". Each node consumes its uSID by shifting the rest of the address left by 16 bits. Up to six uSIDs fit in one address, so most paths need no SRH, and the overhead becomes comparable to an MPLS label stack.

The control plane is the BGP VPN machinery of Chapter 6: RDs, RTs, VPNv4 routes, import and export (RFC 9252). The only change is that instead of a VPN label, the egress PE advertises an **SRv6 SID** with an End.DT4 (or End.DT6, End.DT46) behaviour bound to the VRF.

The ingress PE encapsulates the customer's IPv4 packet in IPv6 with that SID as the destination. The core routes it on the locator prefix, using nothing but IS-IS and IPv6. The egress PE matches the SID, removes the outer header, and looks up the inner packet in the VRF. One address does the jobs of both the transport label and the VPN label.

## Hands on: an SRv6 L3VPN

The lab `labs/lab7-srv6` is the familiar five-router core, but **IPv6-only**: no IPv4 addresses in the core, no MPLS, no LDP. Each router has a uSID locator, `fcbb:bb00:N::/48`, advertised in IS-IS. The PEs carry VRF RED with ce1 and ce2.

> **Requirements.** SRv6 needs a recent kernel (6.1 or newer for uSID forwarding) and a recent FRR. The topology sets `net.vrf.strict_mode=1`, which the kernel requires for End.DT4, and enables SRv6 processing (`seg6_enabled`) on every interface. IS-IS in FRR also expects a dummy interface named `sr0`, which the topology creates. SRv6 support in FRR has changed between releases more than the MPLS features in this book; if a command is rejected, check the FRR documentation for your version.

The key configuration on pe1:

```text
segment-routing
 srv6
  encapsulation
   source-address fc00:0:1::1
  exit
  locators
   locator MAIN
    prefix fcbb:bb00:1::/48
    format usid-f3216
   exit
  exit
 exit
exit
!
router isis CORE
 segment-routing srv6
  locator MAIN
 exit
exit
!
router bgp 65000
 neighbor fc00:0:2::1 remote-as 65000
 neighbor fc00:0:2::1 update-source lo
 segment-routing srv6
  locator MAIN
 exit
 address-family ipv4 vpn
  neighbor fc00:0:2::1 activate
 exit-address-family
exit
!
router bgp 65000 vrf RED
 sid vpn per-vrf export auto
 address-family ipv4 unicast
  redistribute static
  rd vpn export 10.0.0.1:10
  rt vpn both 65000:10
  export vpn
  import vpn
 exit-address-family
exit
```

Compared with the MPLS L3VPN, `label vpn export auto` has become `sid vpn per-vrf export auto`, and the BGP session runs between IPv6 loopbacks. Everything else is the same.

## Choosing a transport

| | LDP | SR-MPLS | SRv6 |
|---|---|---|---|
| Data plane | MPLS | MPLS | IPv6 |
| Control protocols | IGP + LDP | IGP only | IGP only |
| Explicit paths | Needs RSVP-TE | Label stack | SID list |
| Fast reroute | LFA, remote LFA | TI-LFA | TI-LFA |
| Overhead per segment | 4 bytes | 4 bytes | 16 bytes (2 with uSID) |
| Hardware support | Universal | Universal | Recent platforms |
| Crosses non-MPLS networks | No | No | Yes, any IPv6 path |

In practice:

- **Existing MPLS networks** are mostly migrating from LDP (and RSVP-TE) to **SR-MPLS**, which reuses the same hardware and services while removing protocols and state.
- **New networks**, especially those built on IPv6 and on merchant silicon, increasingly choose **SRv6 with uSIDs**, which removes MPLS entirely and lets services reach into data centres and hosts.
- **The services do not change.** L3VPN, EVPN, and SR policies look the same to customers whichever transport carries them. That is the lasting lesson of MPLS: separate the service from the transport, and you can change either one without the other.

## Summary

- **SRv6** encodes segments as **IPv6 addresses**: a **locator** routed by IS-IS, and a **function** (behaviour) such as End, End.X or **End.DT4**.
- Multiple segments travel in an **SRH**; **uSIDs** pack up to six segments into one address.
- **L3VPN over SRv6** uses the same BGP VPN machinery, advertising an **End.DT4/DT6 SID** per VRF instead of a VPN label.
- In FRR, define a **locator**, enable it in **IS-IS** and **BGP**, and use **`sid vpn per-vrf export auto`** in the VRF.
- **SR-MPLS** suits existing MPLS networks; **SRv6** suits new IPv6 networks; the **services** stay the same.
